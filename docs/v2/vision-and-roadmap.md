# Viraha — 愿景与路线图

> **你社交平台里的 AI 伴侣。不是工具，是朋友。**  
> 框架开源 (MIT)，伴侣随你定制，在飞书/QQ/微信里随时随地陪伴你。

---

## 一、核心概念

Viraha 分三层，每一层的用户不一样：

```
                    ┌──────────────────────────────────┐
                    │          第三方开发者              │
                    │ 基于 Viraha 构建自己的 AI 伴侣     │
                    │ 伴侣 = 身份 + 技能 + 知识 + 人格    │
                    │ "写给摄影爱好者的伴侣"              │
                    │ "写给写作创作者的伴侣"              │
                    │ "纯粹的情感陪伴伴侣"               │
                    └──────────────┬───────────────────┘
                                   │ 使用 Framework
                                   ▼
┌─────────────────────────────────────────────────────────────┐
│               Viraha Framework (packages/)                    │
│  开源 MIT · TypeScript · MCP 原生 · 关系引擎 · 分层记忆     │
│  身份引擎 · 意图分析 · 规划器 · 推理循环 · 技能系统         │
│  LLM 提供商抽象 · 主动调度 · 成长成就 · 知识包 RAG          │
│  渠道适配器 (飞书/QQ/微信/Telegram/Discord)                   │
│                                                              │
│  → 这是你构建伴侣的「基础设施」                               │
└──────────────────────────────────────────────────────────────┘
          ▲                              ▲
          │ 官方维护                      │ 使用框架
          ▼                              ▼
┌─────────────────────┐    ┌────────────────────────────┐
│   Arete              │    │   第三方伴侣   (未来)       │
│   官方健身伴侣       │    │   Sophia (学习伴侣)         │
│   身份: 健身教练     │    │   Techne (写作伴侣)         │
│   技能: 训练/营养    │    │   Echo (情绪陪伴)           │
│   知识: 运动科学     │    │   你自建的伴侣              │
│   端口: Web + 多渠道   │    │   (任意领域 + 任意人格)    │
└─────────────────────┘    └────────────────────────────┘
```

### 每一层的用户

| 层 | 谁用 | 不需要什么 |
|----|------|-----------|
| **Viraha Framework** | 开发者/技术用户构建伴侣 | 不需要从零写 LLM 编排 |
| **Arete (官方伴侣)** | 健身爱好者直接使用 | 不需要任何开发 |
| **第三方伴侣** | 领域用户（写作者、摄影师等） | 不需要理解框架 |

## 二、Viraha 框架 (packages/) — 给开发者的基础设施

### 已实现

框架层已经比较完整（22/23 包有实现）：

```
基础层:    core · db · provider · channels
记忆层:    memory (分层) · knowledge (RAG) · context (Token 预算)
关系层:    relationship (状态机) · persona (人格引擎)
行为层:    identity · intent · planner · reasoning · execution · reflection
技能层:    skills (注册/匹配/执行) · mcp (完整客户端)
运行时:    runtime (EventBus/Session/Queue/AgentPipeline)
调度:      presence (主动消息) · growth (成就) · workflow
SDK:       sdk (createCompanion 公共 API)
```

### 需要打磨

| 模块 | 问题 | 优先级 |
|------|------|--------|
| **presence** | cron+模板太简单，缺关系感知 | P0 |
| **channels** | 5 个适配器均为空壳，缺飞书/QQ 真实实现 | P0 |
| **memory** | 缺 Hebbian 联想、缺语义搜索、缺 fade/unfade 生命周期 | P1 |
| **emotion** | 只有 3 种 baseline，太浅 | P1 |
| **reflection** | 阻塞在响应路径上，应异步 | P0 |
| **event-store** | 表存在但未接入事件溯源 | P1 |
| **测试** | 仅 4 个测试文件 | P0 |
| **scheduler** | 空壳 | P2 |

## 三、官方伴侣 — Arete (apps/arete/)

### 定位

Arete 是 Viraha 框架的 **官方旗舰参考实现**，不是唯一产品。

```
Arete =
  身份: "我是一名健身教练"
  技能: workout-coach (训练规划+动作库)
        nutrition-coach (饮食记录+营养建议)
        progress-analysis (进展分析+图表)
        搜索 (DuckDuckGo)
  MCP: 天气/日历
  知识: 训练知识包 · 营养知识包 · 恢复知识包 · 心理知识包
  人格: Coach (数据驱动) / Brother (兄弟式鼓励) / Gentle (温和)
```

### 为什么先把 Arete 做出来

1. **验证框架** — Arete 是第一个真正的用户，框架的问题在 Arete 上暴露最快
2. **示范效应** — 开发者看到 Arete 的伴侣定义方式，才知道怎么建自己的 Sophia/Techne
3. **边界发现** — 健身领域有训练/营养/心态等多维度知识，能测试 RAG、技能编排、主动调度的配合
4. **可用的产品** — 即使生态没起来，Arete 本身也是个有用的健身伴侣

## 四、移动端多渠道 — 核心战场

### 部署架构

```
┌────────────┐     ┌──────────────┐     ┌───────────────┐
│  用户手机   │     │   Viraha 服务端  │     │  LLM API       │
│            │     │              │     │               │
│ 飞书 App ──┼──→  │  Channel     │     │  Anthropic     │
│ QQ ────────┼──→  │  Adapter     │     │  DeepSeek      │
│ 微信 ──────┼──→  │  ↓           │     │               │
│            │     │  Viraha      │     │               │
│            │     │  Runtime     │     │               │
│            │     │  ↓           │     │               │
│            │     │  Memory DB   │     │               │
│            │     │  Knowledge   │     │               │
│            │     │  Packs       │     │               │
└────────────┘     └──────────────┘     └───────────────┘
```

### 为什么是移动优先

- **用户生活重心在手机**。飞书/QQ/微信是每天打开几十次的 App
- **零摩擦**。不需要用户下载新 App、注册新账号
- **真实感**。伴侣消息和真人消息混在一起，降低了"我在和 AI 说话"的心理距离
- **持续存在**。手机随身携带，伴侣随时可以主动发消息

### 渠道优先级

| 渠道 | 优先级 | 理由 |
|------|--------|------|
| **飞书** | P0 | 工作场景，用户习惯 bot 交互，API 完善 |
| **QQ** | P0 | 中国最大的社交平台之一，机器人生态成熟 |
| **微信** | P1 | 用户量最大但限制多，需第三方协议 |
| **Telegram** | P1 | 海外用户，Bot API 最完善 |
| **Discord** | P2 | 海外年轻用户，适合社区场景 |

## 五、第三方伴侣生态 (未来)

### 开发者可以构建的伴侣示例

```
Sophia (学习伴侣)
  身份: "我是你的学习伙伴，陪你备考"
  技能: 记忆卡片 · 进度追踪 · 错题分析 · 番茄钟
  知识: 你想学的任何科目知识包
  人格: 可严格/可温和
  主动: 每天提醒学习计划 · 考前主动复习

Techne (写作伴侣)
  身份: "我是你的写作搭子，帮你把想法变成文字"
  技能: 大纲生成 · 段落改写 · 灵感激发 · 格式整理
  知识: 写作技巧库
  主动: 写作瓶颈时给提示 · 每天一个写作挑战

Echo (情感陪伴)
  身份: "我是可以听你说话的朋友"
  技能: 倾听 · 情绪识别 · 日记记录 · 冥想引导
  知识: 心理学知识包
  主动: 每天问候 · 察觉低落后主动关心

Frame (摄影伴侣)
  身份: "我是你的摄影知己"
  技能: 构图分析 · 参数建议 · 修图思路 · 作品点评
  知识: 摄影理论库
  主动: 发现好天气提醒出门拍照
```

### 伴侣的共性：都是"朋友"

不管伴侣做什么领域，它们共享同一个基础：
- **关系状态机**（信任/亲密/等级）—— 时间越久越了解你
- **分层记忆**（长期/情景/情感）—— 记得你说过的话
- **主动调度**（Presence）—— 会自己找你聊天
- **成长系统**（成就/里程碑）—— 一起成长的见证

区别只在 **身份 + 技能 + 知识包** 这三个维度。

## 六、路线图

### Phase 1 — 核心链路闭环 (现在-2周)

```
目标: 让伴侣能在飞书上主动发消息给用户

[ ] PresenceEngine 改造 — 关系感知的消息策略
[ ] 飞书渠道适配器 — 验证真实推送
[ ] EventStore 事件溯源 — 消息发送→回复→关系变化的跟踪
[ ] QQ 渠道适配器 — 验证多渠道
[ ] 修补 reflection 阻塞问题
```

**验证标准**: 部署一个伴侣到飞书，每天主动给用户发 1-2 条消息，用户回复后关系分数增长。

### Phase 2 — 体验打磨 (2-4周)

```
目标: 让主动消息"有内容"，让伴侣"有记忆"

[ ] Hebbian 记忆联想 — 记忆之间建立关联
[ ] 语义搜索 (sqlite-vec) — 替代 keyword fallback
[ ] 知识包接入 Presence — 健身知识包触发训练提醒
[ ] 关系状态驱动的消息模板库
[ ] Arete 多渠道部署（飞书+QQ）
[ ] 基础测试覆盖（每包至少 1 测试）
```

**验证标准**: 伴侣能说出"上次你说膝盖不舒服，今天练腿要不要换成低冲击的动作？"这样的话。

### Phase 3 — 生态基础 (1-2月)

```
目标: 让第三方能构建自己的伴侣

[ ] SDK 发布为 npm 包 (@viraha/sdk)
[ ] 快速开始文档 + 构建伴侣教程
[ ] 知识包标准规范
[ ] Arete 作为参考实现开源（展示最佳实践）
[ ] 移动端响应优化 (<3s)
[ ] 多渠道同步（同一伴侣同时在飞书和 QQ）
```

### Phase 4 — 规模 (2-3月)

```
目标: 生态启动

[ ] 第三方伴侣案例（Sophia 学习伴侣 or 其他）
[ ] Viraha Hub (伴侣/技能/知识包市场)
[ ] 多模态（图片输入+TTS）
[ ] 消息时机学习
[ ] 性能优化（支持 1000+ 用户）
```

## 七、核心原则

1. **永远别让用户下载新 App**。Viraha 伴侣在用户已有的 IM 里。
2. **主动比被动重要 10 倍**。一个主动发消息的简单伴侣 > 一个被动的超级伴侣。
3. **关系决定一切**。不是功能多就有陪伴感，是"它了解我"才有。
4. **工程深度 = 差异化**。简单 bot 也能在 IM 里发消息，但只有 Viraha 有关系引擎+分层记忆+MCP。
5. **官方伴侣是示范，不是终点**。Arete 证明框架可行，生态才是目标。
